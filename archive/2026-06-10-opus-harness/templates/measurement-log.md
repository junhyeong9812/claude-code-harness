# 측정 로그 (Measurement Log)

> 위치: **대상 프로젝트** `docs/measurement-log.md`. 작업당 **<1분** 기록.
> 목적: 하네스 컴포넌트의 ROI를 "느낌"이 아니라 데이터로 — `orchestration.md §6 점검`의 입력.
> 기반: `docs/11-하네스-재설계-제안.md` E축, `docs/13-변경맵`.

---

## 기록 (작업당 1행)

| 날짜 | 작업 | 유형 | 규모 | stakes | 총소요 | 하네스 오버헤드 | 재작업 횟수 | 테스트실패후 수정 | 검증서 잡은 실제 결함 | 오탐 | 머지후 결함 | 생략한 게이트 + 결과 |
|------|------|------|------|--------|--------|----------------|------------|------------------|----------------------|------|------------|----------------------|
| | | | | | | | | | | | | |

> 컬럼 의미:
> - **하네스 오버헤드**: 게이트·문서·codex 대기 등 하네스 때문에 든 시간.
> - **검증서 잡은 실제 결함**: 리뷰/codex/테스트가 *실제로* 잡은 결함 수(오탐 제외).
> - **생략한 게이트 + 결과**: 어떤 규칙을 건너뛰었고, 그 결과 사고가 났나/없었나. ← 어떤 규칙이 실제 필요한지의 직접 증거.

---

## 주기 분석 판단식 (§6 점검)

```
유지 = 실제 결함/재작업을 줄인 증거가 있고 + 작업당 오버헤드 낮음
축소 = 가끔 가치 있지만 상시 적용 비용이 큼
삭제 = 설명은 그럴듯한데 측정 효과 없고 문서/판단 비용만 늘림
```

## A/B (선택)

- 2주 현행 / 2주 축소판 → `총소요 · 재작업률 · 실제 결함 발견 수 · 오탐 수 · 머지 후 결함` 비교.
- 첫 축소판 기간엔 **보수적 승격**(놓친 결함 비용 방어).
