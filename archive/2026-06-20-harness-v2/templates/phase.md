# 페이즈 폴더 양식 (phases/phase-NN-이름/)

> stakes 높음 **중 다단계·대규모** 전용 (단일 페이즈 높음은 definition+task.md — core §5). 페이즈당 **3파일**: `spec.md`(계획+테스트 설계) / `changes.md`(실제 변경) / `gate.md`(검증 결과).
> 분리의 본질은 파일 수가 아니라 **작성 시점·컨텍스트**다: 테스트 설계는 구현 diff를 보기 전에 spec에 먼저 쓴다 (playbooks/orchestration.md 절단 계약).

---

## spec.md — 계획 (구현 전 작성, 사용자/메인 확정)

```markdown
# phase-NN: {이름}
> 마스터: ../../master-plan.md / 선행: (페이즈 또는 없음)

## 1. 목표 (단일 의도, 중간 검증 가능 단위)
## 2. 변경 파일        | 경로 | 변경 내용 | 신규/수정 |
## 3. 변경 금지        | 파일/영역 | 이유 |
## 4. 완료 조건 (acceptance)
## 5. 검증 명령 (구체적으로 — 가벼운 명령으로 통과 처리 금지)
   기대 결과: (예: "21 tests green", "source=target=1288471")
## 6. 테스트 설계 ★구현 diff 미열람 — spec·정의만 보고 작성★
   | 케이스 | 검증하는 불변식/실패 의미론 | 방법 |
   (예외 경로 최소 1개 포함 — playbooks/verification.md)
   - 작성 시점: (구현 착수 전) / 입력으로 본 문서: (spec·definition만)
## 7. 실패 시 되돌릴 범위 (롤백 단위 — 사용자 승인 후)
## 8. spec 고정: 이 시점에 커밋(또는 해시 기록) 후 구현 진입. 이후 spec 변경은 시점·사유를 §8에 추가
```

## changes.md — 실제 변경 (구현 후, git diff 기준)

```markdown
# phase-NN changes
> 계획(spec)이 아니라 **결과**를 기록한다. 코드는 파일에서 직접 복사 — 메모리 재현 금지.

## 변경 요약   | 파일 | 무엇이 바뀌었나 |
## 주요 변경 스니펫 (의미 단위 전체 — `...생략` 금지, 출처 `파일:라인`)
## spec과 달라진 점 (없으면 "없음")
```

## gate.md — 검증 결과 (게이트 판정, 메인 작성)

```markdown
# phase-NN gate
## 빌드/테스트: (명령 + 결과 — 실제 출력 요약)
## 예외 경로 테스트: (케이스별 통과 여부)
## 플로우 디버깅 (해당 시): (API 실호출·서비스 간 경계 — playbooks/verification.md)
## 절단 확인: 테스트 설계가 구현 전 작성·diff 미열람이었나 □ / spec 변경 있었으면 시점·사유 확인 □
## 리뷰: (구현자와 분리된 컨텍스트 — finding은 이 페이즈 diff에 귀속 증명, 범위 밖은 별도 표기)
## codex 독립 검증 (stakes 높음): (호출 ID·지적·채택/기각)
## 판정: 통과 / 실패(사유) — 통과 시 이 페이즈 파일만 커밋 후 다음 진입
```
