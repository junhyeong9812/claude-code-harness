# dimensions-frontend.md — 프론트엔드 확장팩

> 로딩: dimensions.md surface detector — 브라우저/앱에서 실행되는 UI 코드일 때.
> 기본 14차원에 **추가**한다 — **팩은 기본 차원을 끄는 근거가 아니다** (같은 질문을 두 번 쓰지 않을 뿐, 2 입력검증·11 보안·17 가시성은 기본 차원에서 그대로 판정). F행으로 덧붙인다.
> 연동: F7에서 PII를 다루면 기본 11 보안을 활성으로 올린다.

### F1 상태 동기화
- F1-T: 서버 상태의 사본(캐시·스토어·낙관적 업데이트)을 클라이언트가 들고 있는가?
- stakes: 활성=중간
- F1-P: 서버와 불일치 시 무엇이 이기나? 낙관적 업데이트 실패 시 롤백은?
- F1-V: 실패 응답 후 UI 상태가 서버 상태로 복원되는지 확인했나?

### F2 호환성
- F2-T: 특정 브라우저·디바이스·뷰포트에서만 검증하고 있는가?
- stakes: 활성=낮음↑ · 주 사용층 디바이스 미검증이면 중간
- F2-P: 지원 범위(브라우저·뷰포트) 정의가 있나?
- F2-V: 지원 범위 대표 환경에서 확인했나?

### F3 접근성 (a11y)
- F3-T: 인터랙티브 요소·폼·동적 콘텐츠를 만들거나 바꾸는가?
- stakes: 활성=낮음↑ · 공공·대규모 서비스면 중간
- F3-P: 키보드 내비게이션·포커스 순서·시맨틱/ARIA·대비는?
- F3-V: 키보드만으로 플로우를 완주할 수 있나?

### F4 클라이언트 성능
- F4-T: 번들 크기·렌더링 비용·리스트 크기에 영향을 주는가?
- stakes: 활성=낮음↑ · 핵심 진입 경로면 중간
- F4-P: 새 의존성의 번들 영향은? 대량 리스트 가상화·지연 로딩은?
- F4-V: 렌더링·로딩 지표를 변경 전후로 봤나?

### F5 i18n/l10n
- F5-T: 사용자에게 보이는 문자열·날짜·숫자·통화 형식을 추가·변경하는가?
- stakes: 활성=낮음↑ (다국어 서비스면 중간)
- F5-P: 하드코딩인가 리소스 분리인가? 형식은 locale을 따르나?

### F6 오프라인·캐시 무효화
- F6-T: 클라이언트 캐시(HTTP·SW·로컬 스토리지)에 데이터를 두는가?
- stakes: 활성=중간 (stale 데이터가 잘못된 행동을 유발하면)
- F6-P: 무효화 전략은? 배포 후 구버전 캐시·코드와의 공존은?
- F6-V: 배포 직후 구캐시 사용자 시나리오를 확인했나?

### F7 분석·프라이버시
- F7-T: 사용자 행동 데이터를 수집·전송하는가?
- stakes: 활성=중간 · PII 포함이면 높음
- F7-P: 동의 처리·수집 최소화는? 전송 데이터에 PII가 섞이나?
