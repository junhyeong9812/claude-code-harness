## 1. 무엇을 보고 결정하나 (로그 → 신호)

`measurement-log.md`의 각 컬럼이 어떤 결정 신호인지:

| 로그 신호 | 무엇을 말하나 |
|-----------|---------------|
| **검증서 잡은 실제 결함** = 0 이고 **하네스 오버헤드** 큼 | 그 검증은 비용만 큼 → 축소 후보 |
| **머지 후 결함** 증가 | 검증이 부족 → 축소 금지(오히려 강화) |
| **오탐 수** 큼 | 리뷰/페르소나가 노이즈 생성 → 해당 렌즈 축소 |
| **재작업 횟수** 큼 | 방향/정의 품질 부족 → 게이트(T4 정의) 강화 |
| **생략한 게이트 + 결과** = "생략했는데 사고 없음" 반복 | 그 게이트는 약화 가능 |
| **생략한 게이트 + 결과** = "생략했더니 사고" | 그 게이트는 유지·강화 |

> 판단식(§6 점검):
> ```
> 유지 = 실제 결함/재작업을 줄인 증거 + 작업당 오버헤드 낮음
> 축소 = 가끔 가치 있지만 상시 비용 큼
> 삭제 = 설명만 그럴듯 + 측정 효과 없음 + 문서/판단 비용만 늘림
> ```

## 2. 2주 프로토콜

```
주 0      : 로그 시작. 모든 작업 1행씩. 솔직하게(생략한 게이트도 기록).
주 1~2    : 베이스라인 축적 (현행 그대로, 아무것도 안 줄임).
주 2 분석 : 컴포넌트별로 §1 신호 집계 → §3 결정.
선택 A/B  : 이후 2주 "축소판" → 총소요·재작업·실제결함·오탐·머지후결함 비교.
```

- **최소 표본**: 컴포넌트당 의미 있는 판단엔 ~10건+ 권장. 적으면 보류.
- **첫 축소판 기간**: 보수적 승격(놓친 결함 비용 방어).

## 3. 컴포넌트별 결정 규칙 (데이터 → 액션)

| 컴포넌트 | 축소(P3~P5) 정당화 조건 | 축소 금지 신호 |
|----------|------------------------|----------------|
| **codex 빈도(A)** | 저stakes 작업들에서 "codex가 잡은 실제 결함 ≈ 0" + 오버헤드 누적 큼 | 저stakes에서도 codex가 결함을 자주 잡음 → 빈도 유지 |
| **페이즈 6파일(C)** | 문서 동기화 부채(코드와 어긋남) 발생 + 재사용 거의 안 함 | test-design/changes가 실제 격리·재사용에 쓰임 |
| **페르소나 렌즈(D)** | 특정 렌즈 오탐 > 실제결함 | 렌즈가 실제 결함을 잡음 |
| **named-expert(D)** | 파이프라인서 결함 기여 측정 불가 + 유지비만 | (학습용 가치는 측정과 별개로 유지) |
| **게이트(B2.5 등)** | "생략해도 사고 없음" 반복 | 생략 시 재작업/결함 증가 |

> ★ 모든 축소는 **H(최소 안전선)을 절대 건드리지 않는다.** 줄이는 건 "비싼 검증의 빈도"지 "머지 전 바닥"이 아니다.

## 4. P3 시작 트리거

```
IF (로그 ≥ 10건/컴포넌트) AND (신호 안정적) AND (머지후 결함 비증가):
    → §3 표로 축소 대상 확정
    → P3(A축: stakes→codex 빈도 연결) 먼저, 그다음 C·D
    → 각 축소 후 다시 2주 측정 (머지후 결함 감시)
ELSE:
    → 측정 계속, 축소 보류
```

- **P3 = CLAUDE.md 원칙 5·6 개정** (큰 변화) — 반드시 데이터 근거가 있을 때만.
- 축소 후 **머지후 결함이 늘면 즉시 롤백**(git revert) + 그 게이트 복원.

## 5. 안전 원칙 (축소의 가드레일)

1. **H(최소 안전선)·G(승격)은 영구.** 축소 대상 아님.
2. **한 번에 한 축소.** A 줄이고 2주 → C 줄이고 2주 → D. 동시 금지(원인 추적 불가).
3. **머지후 결함 = 최종 심판.** 이게 늘면 그 축소는 틀린 것.
4. **솔직한 로그가 전제.** "생략한 게이트"를 숨기면 데이터가 거짓이 되고 플레이북이 무의미.

## 6. codex 역할 재정의 (이번 수정 — 빈도와 분리)

> 빈도(A)는 측정 대기. 하지만 **codex 출력을 *어떻게 쓰나*는 지금 바꾼다** — 안전성을 안 낮추므로.

**변경**: 리서치 단계(B1.6/A1.6/C1.6)의 codex 역할 = **"검증 관문"이 아니라 "선택지 보강·체크리스트 추출기"**.
- 통과/실패 판정 ❌ → Claude가 못 본 **대안 접근·선택지**와 **점검 항목** 발굴 ✅.
- 출력은 B2 방향성 결정의 **옵션 메뉴를 넓히는 입력**으로 소비(승인 도장 아님).
- LLM 다수결 편향을 *'승인'*이 아니라 *'선택지 확장'*으로 보정.

**왜 지금 해도 안전한가**: codex가 도는 *빈도*는 그대로(전면 의무 유지) → 검증 커버리지 안 줄어듦. *소비 방식*만 "관문→보강"으로 바뀜. 오히려 다수결 편향 보정이 강해진다.

> 적용 위치: `orchestration-impl.md` B1.6 목표 · `orchestration-agent.md` 11.2 · `templates/codex-prompt.md` "2. 모델 교차 분석". (plan/진단/테스트 검토(프롬프트 3·4·5)는 *검증*이 맞으므로 그대로.)
