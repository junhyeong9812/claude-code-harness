# 설계 제안: 하네스 재설계 (Stakes-Proportional Harness)

> 작성일: 2026-06-09
> 모드: 설계 제안 (구현 아님 — 검토용). 채택 시 점진 적용.
> 배경: `09`(개발=경계 정의) → `10`(B2.5 정의 게이트) → 본 문서 직전 2라운드 실용성 평가.
> 검증: codex(GPT-5.5) 교차검증 (§11 기록). **본 제안은 오늘 추가한 B2.5를 일부 되돌린다(§10 정직 노트).**

## 0. 한 줄 결론

> 하네스의 **뼈대는 유지**하되, "항상 많이 검증한다"를 **"위험에 비례해 독립성을 확보한다"**로 바꾼다.
> 핵심은 검증을 *줄이는 것*이 아니라, **"누가·언제·무엇 기준으로 검증을 올리는가"(승격 규칙)와 "아무리 낮아도 통과해야 할 최소선"(universal floor)**을 명시하는 것. 이 둘이 없으면 축소는 누락 허용이 된다(codex 핵심 경고).

---

## 1. 관통 원칙 2개

1. **학습 스캐폴드 ≠ 프로덕션 게이트.** 지금 무거운 장치(codex 전면 의무·named 페르소나·6파일)는 7개월 차 *학습 보조*로는 가치가 크나 *영구 게이트*로는 과조정. → 재배치(삭제 아님).
2. **하네스는 성장할수록 줄어드는 비계.** 각 catch를 값싼 체크리스트로 졸업시키면 비싼 도구(codex/페르소나)가 점점 덜 필요. 외골격이 아니라 비계.

## 2. 바꾸지 않는 것 (강한 뼈대 — 명시)

축소안이 "다 갈아엎기"로 오해되지 않게 **유지 항목을 먼저 못 박는다**:

- 모드 라우터 · 작업 기준 확정 게이트 · 유형×규모 분류
- B2 방향성 · A2 진단 · C2 목표 게이트
- **6.6 데이터/마이그레이션 검증**(source/target count·orphan·sample diff) — 사용자 최고가치 작업, 그대로
- hooks 5종 · single-change 규율 · 페이즈마다 커밋
- domain-contracts.md · learned.md(짧게)

## 3. 재설계 8축

### A. 검증(codex/큐레이션): 균일 의무 → stakes 트리거 3단계 ★최우선★

| | 현행 | 제안 |
|---|------|------|
| 구현 | 모든 단계 codex 의무 | **stakes 트리거**로 |
| 토론 | 답변당 1회 의무 | 고위험 결정·장기 설계안만 |

**3단계 (stakes = 틀렸을 때 손실·낯섦·모호성·반복오류 — "기능 크기" 아님)**:
- **낮음**: 자체 체크리스트(+ §B 정의 3문항 + §A-반증질문)
- **중간**: targeted codex 1회 (또는 동등한 독립 검증)
- **높음**: 외부 큐레이션 + codex + 별도 검증

**유지할 학습 루프**: codex 지적을 "승인 도장"으로 쓰지 않고 **"이번에 놓친 패턴"을 추출해 체크리스트로 졸업** → 다음부터 본인이 잡음(F축 연료).

**반증 질문 (낮음에도 필수 — 자기검증 맹점 차단, codex 추가)**:
- 이 변경이 의도와 다르게 적용될 다른 호출 경로는?
- 데이터가 비어/중복/오래된 경우는?
- 권한 없는 사용자가 같은 경로를 밟을 수 있나?
- 테스트가 실제 실패 모드를 재현하나, 구현을 따라간 happy path인가?

### B. B2.5 정의 게이트: 독립 게이트 → B2/C2 안의 3문항 체크 (격하)

3문항: ① 모호한 용어/완료조건 있나 ② 경계별 불변식·실패 시 동작 정의됐나 ③ 비대상(범위 밖) 명확한가.
- **답이 애매하면 → "그냥 진행" 금지, 중간 이상으로 승격**(codex 보정 — 모호성은 진행 사유가 아니라 승격 사유).
- `definition.md`는 대/고위험·데이터에서만 선택적 산출물. 전 작업 의무 아님.

### C. 페이즈 문서: 6파일 → "섞이면 안 되는 것"만 파일 분리

- 분리 기준 = "작게"가 아니라 **정보 격리 · 재사용 · 검증 계약**(codex).
- **파일 유지**: `test-design`(impl 미열람 계약), `changes`(diff/재사용) — *진짜 분리 워커가 쓸 때만*.
- **섹션으로 합침**: `spec`/`gate`/`review`/`codex-verify` → `phase-N.md` 섹션 (메인이 순차로 쓰면).
- 즉 "6 전부 유지"도 "1로 합쳐라"도 아님 — **격리 계약 있는 것만 파일**.

### D. 페르소나: 두 집으로 분리

- **프로덕션 파이프라인**: 구조적 역할분리(생성≠검증·test-design 분리·review 게이트) + 고정 **리뷰 렌즈 5개** 체크리스트만 — 데이터 무결성 / 장애·운영 / 보안 / API 계약 / 테스트 가능성.
- **학습 레퍼런스**: named-expert 라이브러리를 **"학습 인덱스"로 격하** — 파이프라인 캐스팅 제거, 낯선 도메인서 *체크리스트 발견용*으로만. 산출물은 항상 이름이 아니라 체크리스트("DDD 관점" ❌ → "aggregate 경계·invariant 위치·transaction boundary·repository 책임" ✅).

### E. 측정 레이어 신설 ★없으면 전부 "느낌"으로 끝남★

작업당 <1분 로그: 유형/규모 · 총 소요 · 하네스 오버헤드 · 재작업 횟수 · 테스트 실패 후 수정 · **검증서 잡은 실제 결함** · 오탐 수 · 머지 후 결함 · **생략한 게이트 + 그 결과**.
- 운영: **2주 현행 / 2주 축소판 A/B**.
- 판단식: 유지 = 결함·재작업 줄인 *증거* + 저비용 / 삭제 = 설명만 그럴듯 + 측정 효과 없음.
- **첫 축소판 기간엔 보수적 승격**(codex — A/B 사이 놓친 결함 비용 방어).

### F. 메타 원칙: 성장할수록 줄어드는 비계

각 catch를 체크리스트로 졸업 → 비싼 도구 점점 덜 필요. §6 점검 루프 + E축 측정 = 가지치기 메커니즘. (단 codex 경고: A·E 없으면 F는 선언에 그침.)

### G. 승격 규칙 (escalation) ★codex 추가 — 빠지면 안 됨★

낮음→중간/높음으로 **올리는 트리거**를 명시:
- 테스트 설계가 막힘 (불변식이 안 잡힘)
- 불변식을 한 문장으로 설명 실패
- 예상 diff보다 변경이 확산
- 리뷰 중 새 경계 발견
- 같은 곳 **2회 이상 수정**(13.2와 동일 임계)
- 모호성 미해소(§B)

### H. 머지 전 최소 안전선 (universal floor) ★codex 추가 — 빠지면 "누락 허용"★

**아무리 낮음이어도** 통과해야 하는 공통선:
- 관련 테스트 실행 (또는 *실행 불가 사유* 기록)
- diff self-review (의도 외 변경 없나)
- rollback/복구 가능성 판단
- **public contract 영향 확인** (API·DB·이벤트 경계)

### "낮음"의 정의 (codex — "작다"가 아님)

> 낮음 = blast radius가 작고, invariant가 명확하며, 실패해도 복구 쉽고, **기존 테스트가 의미 있게 막아주는** 변경.

**낮음으로 두면 안 되는 경계** (작아 보여도 중간↑):
- 사용자 데이터 생성/수정/조회 *의미*가 바뀜
- 권한·소유권·tenant·role·visibility 조건 포함
- DB query·transaction·uniqueness·pagination·timezone·ordering 변경
- 재시도·중복 실행·partial failure 가능성
- 외부 API·webhook·queue·async job·scheduler 연결
- 테스트가 정상 케이스 1개뿐 / fixture 빈약
- "단순 리팩터"인데 characterization test 없음
- 버그 수정인데 원인이 한 문장으로 안 됨
- 최근 반복 오류 영역과 닿음
- config·env·auth guard·retry·timeout·serialization (diff는 작아도 장애 반경 큼)

## 4. 우선순위 로드맵 (codex 순위)

1. **A 검증 트리거 + G 승격 + H 최소안전선** (한 묶음 — A 혼자면 위험)
2. **B 정의 게이트 격하**
3. **E 측정 레이어** (A 효과를 증명할 유일한 수단)
4. **C 페이즈 문서 축소**
5. **D 페르소나 분리**
6. **F 원칙 명문화**

> A·E·F는 서로 의존: A로 줄이고, E로 측정하고, F로 졸업. **A를 G·H 없이 적용하면 과교정.**

## 5. CLAUDE.md 원칙 5·6 개정안 (전면 수정 의도, 점진 실행 — codex)

**삭제가 아니라 재정의** — "항상 많이 검증" → "위험에 비례해 독립성 확보":

```
- 고위험(불가역·보안·데이터손실·마이그레이션·public API·낯섦·모호): 외부 큐레이션 + codex 필수
- 중위험: targeted codex 또는 동등한 독립 검증 필수
- 저위험: 체크리스트 허용 — 단 ① 승격 조건(§G) 발견 시 즉시 상향 ② 최소 안전선(§H) 통과 ③ 반증 질문 포함
- 생략한 게이트는 측정 로그(§E)에 남기고 사후 결함과 연결
```

## 8. (참고) 본 제안이 오늘 작업과 충돌하는 부분 — 정직 노트

오늘 세션에서 **B2.5 정의 게이트를 독립 게이트로 신설**했는데, 본 재설계는 그것을 **B2/C2의 3문항 체크로 격하**한다(§B). 즉 같은 날 추가한 것을 같은 날 다이어트하자는 제안이다. 이건 실수가 아니라 **하네스의 재귀 위험(좋은 아이디어가 계속 게이트로 굳는 것)을 실시간으로 보여주는 사례**다 — 그래서 E축(측정)과 F축(졸업)이 없으면 시스템은 단조 증가한다. definition.md 템플릿·domain-contracts.md는 유지(선택적 산출물로 가치 있음), 다만 "전 작업 게이트"라는 강제력만 격하.
