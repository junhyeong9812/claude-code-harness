# writing.md — 필사 가이드 ({작업명})

> **사용자용 따라치기 문서.** 위에서 아래로 순서대로, 각 스텝의 **after 블록을 직접 타이핑**해 구현을 재현한다.
> 이 문서가 **필사 정답의 단일 출처**다(별도 패치·정답 파일 없음 — core §0.1). 막히면 해당 스텝의 after + 설명이 곧 답이다.
> 트리거: 작업 모드 `auto-write`·`lazy-write`의 핸드오프 단계 (`playbooks/write-handoff.md` §2).
> 작성 규칙: 코드 블록은 **롤백 직전 실파일에서 복사**(생략·`...`·placeholder 금지). writing.md만으로 동작 구현이 그대로 재현되어야 한다.

## 진행 방법

1. 각 스텝의 **위치(앵커)**로 파일을 연다 → **after** 블록대로 타이핑한다(before는 바뀌기 전 모습, 대조용).
2. **설명**을 읽고 *왜* 그렇게 바뀌는지 이해한다.
3. 테스트 스텝은 그 테스트가 **무엇을 막는지** 이해하고 작성한다.
4. 전부 끝나면 알린다 → 검증(지적만, 수정은 본인) → 통과까지 반복.

## 변경 순서 인덱스
- [ ] Step 1 — {파일}:{대략 위치} — {한 줄 요약}
- [ ] Step 2 — …
- (구현이 동작하도록 **의존 순서**대로 나열 — 먼저 친 게 다음의 전제가 되도록)

## Step 1 — {파일 경로} ({함수/심볼/섹션 = 앵커})

**무엇/왜**: {이 변경이 다른 코드와 어떻게 연결되는가 · 어떤 문제가 있었나 · 그래서 어떻게 바꾸나}

**before** (대조용 — 바뀌기 전):
```{lang}
{실파일에서 복사한 변경 전 코드 — 신규 파일이면 "신규 파일" 명시}
```

**after** (← 이걸 타이핑):
```{lang}
{실파일에서 복사한 변경 후 코드 — 완전하게, 생략 없이}
```

**테스트** (해당 시): 이 변경의 어떤 실패모드를 막나 → 재현/검증 코드:
```{lang}
{테스트 코드 — 무엇을 검증하는지 설명과 함께}
```
