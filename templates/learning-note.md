# 학습노트: {작업명}

> 목적: **사용자의 학습** — 이 구현의 개념·동작 모델·전이 가능 지식을 정리한다. 구 OVERVIEW·learned·TECHNICAL 3종의 **통합 후신**(v3, core §3.5). 프로세스 기록이 아니라 제품 산출물이다.
> **트리거 (옵트인)**: 기본값은 작성하지 않는다. **사용자가 요청하거나, 높음 stakes + 학습 가치가 클 때만** 작성한다. 그 외 이번 diff의 의사결정·진행 이력은 task-process(완료 요약의 diff 스니펫)가 담당한다.
> 경계: **task-process 완료 요약** = 이번 diff의 선택과 이유·진행 타임라인(before/after 스니펫) / **이 문서** = diff를 몰라도 유지보수자가 이해할 **바탕 개념·동작 모델·사용 요소 카탈로그**. 같은 내용을 두 곳에 쓰지 않는다 — 상세 스니펫은 task-process 완료 요약을 참조한다.
> **⚠️ 작성 전 필수 (core §3.5 인용 규칙)**: 코드 예시는 이번 작업에서 생성/수정한 **실파일을 다시 열어 복사**한다. 메모리 재현·placeholder 금지. 완료 문서 조사는 Opus 워커 위임이 이 규칙의 구조적 집행(§5).

## 1. 개요 (주요 포인트 3~5)

이 구현을 처음 여는 사람이 30초에 잡아야 하는 것. 각 줄: **무엇을 하는가 / 핵심 메커니즘(이름·위험 키워드) / 어디가 까다로운가** + 딥다이브 포인터.

- (예) PTY로 자식 프로세스를 띄워 시그널을 중계한다 — 핵심은 SIGWINCH 전파, 까다로운 곳은 종료 레이스. → §2 동작 모델
- (예) 편집 저장은 md 왕복으로 원본 포맷을 보존한다 — 손실 지점은 표 정렬. → 선택 이유 task-process 완료 요약

## 2. 동작 모델 (diff 비종속)

> 특정 diff를 몰라도 유지보수자가 이해해야 하는 **바탕 개념·런타임 동작·불변조건·상태 소유권·실패 메커니즘**. 다른 프로젝트에 그대로 들고 갈 수 있는 설명만 쓴다. (절차·분기 다이어그램이 필요하면 여기 ASCII로 — v3는 OVERVIEW를 흡수했다.)

### 알아야 하는 개념 (구현 전제 지식)

각 개념: ① 무엇인가(일반 정의) ② 왜 이 작업에 필요했나 ③ 모르면 어떤 결함이 나오나.

- **{개념명}**:

### 동작 방식

핵심 메커니즘이 **런타임에 어떻게 움직이는가** — 자료구조·시그널·프로토콜 수준. "코드가 무엇을 한다"가 아니라 "왜 그렇게 동작할 수밖에 없는가".

### 불변조건 / 상태 소유권 (해당 시)

- 절대 깨지면 안 되는 상태·계약을 한 줄씩 + 깨졌을 때의 증상.
- 어떤 값이 어디에 살고(source of truth) 누가 갱신하나. 파생값은 저장 vs 계산.

### 실패 모드 (해당 시)

- 실패 분기별: 원인 → 증상 → 처리/복구. 왜 그 실패가 일어나는가를 산문으로.

### 해당 없음 사유

- 위 "해당 시" 절을 비웠다면 한 줄 이유 (예: "외부 경계 — 단일 프로세스, 외부 의존 없음").
