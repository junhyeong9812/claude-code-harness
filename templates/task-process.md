# task-process.md — {작업명} (라이브 타임라인)

> 목적: L1 구현의 **단일 라이브 타임라인**. 무엇을 시도→실패→해결→결정했는가를 시간순으로 남긴다 — 감사 추적 + 세션 재개 앵커.
> 위치·소유 (core §3.1): `docs/plans/YYYY-MM-DD/작업명/task-process.md` **단일 파일**. **메인이 단일 writer** — 워커·서브에이전트는 여기 쓰지 않는다(메인이 packet 회수 후 대신 기입).
> 형식: `시각 | 사건 | 결과/결정` 1~3줄. **사건 발생 시점에 append** — 시도→실패→해결→결정, 테스트 단위 구분. **사후 재구성 금지**(끝나고 몰아 쓰면 라이브 로그가 아니다).
>   - 워커 이벤트 예외: 회수 시점에 append하되 `[워커 이벤트 — {task/loop} packet 회수]`로 표시하고 **packet 원시각·순번을 명시**한다. 회수 실패 시 **"미회수" 행 필수**(공백으로 넘기지 않는다).
>   - append는 **Edit 도구**로 한다 — 셸 `cat >>`(입력 없는 heredoc)는 stdin 대기 stall을 유발한다(기지 함정).
> 인용 규칙 (core §3.5): 완료 요약의 코드 블록은 **실파일에서 복사** — 메모리 재현·placeholder 금지. 완료 문서·diff 조사는 Opus 워커 위임이 이 규칙의 구조적 집행(§5).

## 타임라인

> 각 행: `MM-DD [시각대] | 사건 | 결과/결정`. 시각은 알면 시:분, 모르면 오전/오후 정도로. 빈 줄로 라운드·페이즈를 시각 구분해도 좋다.

- (예) 07-19 오후 | 토론 종료 → 정의 게이트 진입 | 6칸 확정, stakes 높음 도출, 모드 auto 선택
- (예) 07-19 | 구현 중 발견: {예상과 다른 사실} | {대응·재계획}, {후속 task} 입력으로 등록
- (예) 07-19 | [워커 이벤트 — task-02 packet 회수] {워커가 한 것·검증 결과} | 메인 교차 확인: {직접 재확인한 것} — 일치/불일치
- (예) 07-19 | 도구 사고 1건: {무엇이 stall/실패} | {정리·전환}, 교훈: {재발 방지}

## fast 빚 (fast 모드 정본 — 그 외 모드는 "없음")

> core §1·§3.4: **fast 모드의 미상환 빚 정본이 여기다**(상태파일 `FAST_DEBT=1`은 플래그일 뿐 — 내용은 이 섹션). 스모크만 즉시, 리뷰·테스트·문서·정의·계획은 여기 빚으로 적재. **해소 전 "작업 완료" 선언 금지**, 차기 L1 진입 시 이 빚부터.

## 완료 요약 (작업 종료 시 — Opus 워커 위임 권장)

> core §3.5: 종료 시 작성. **완료 문서·diff 조사는 Opus 워커에 위임**(실파일 재읽기 강제 — 메인 기억으로 내용 전달 금지). 코드 구현이 없는 문서-only 작업은 3~5줄로 축약.

- **무엇이 됐나**: (목표 대비 최종 상태 — 무엇이 완료됐고 acceptance를 어떻게 충족했나)
- **핵심 diff** (before/after — 실파일 복사, 리뷰 훈련 가치. J급 변경 1~3개):

  `파일경로:라인` — {한 줄 요약}
  ```
  # before
  (실파일 히스토리/diff에서 복사)
  # after
  (현재 실파일에서 복사)
  ```

- **배운 것**: (이번 작업에서 새로 확인·전이 가능한 것 — 깊이 필요하면 학습노트로 승격, §3.5 옵트인)
- **남은 빚/이월**: (미해소 항목·후속 task·범위 밖 관찰. 없으면 "없음")
- **측정 1행**: `docs/measurement-log.md` 기입 완료 □ (사용 워커 모델 포함)
- **review-log**: 中↑ 리뷰가 돌았으면 `review-log.md` 작성 □ (없으면 "해당 없음")
