# playbook: 오케스트레이션 (메인 = 관리감독)

> 트리거: **중간↑ stakes 진입 시 항상** + 낮음이라도 대량 탐색 위임 시 (core §7과 동일).
> 원리: 메인 컨텍스트를 보호해야 긴 작업 후반에도 게이트 판정 품질이 유지된다. 토큰 절약은 부수 효과다.

## 1. 소유권 절단선 — 누가 무엇을 하나

| 메인이 소유 (위임 금지) | 워커에 위임 |
|------------------------|------------|
| 정의 6칸·계획·사용자 합의·게이트 판정·최종 종합 | 대량 파일 읽기·코드베이스 탐색(Explore) |
| stakes 판정·승격 결정 | 독립 모듈 병렬 구현(같은 파일 금지) |
| learned.md (전체 맥락 필요) | 테스트 설계·리뷰·검증 리포트 |

- 메인이 소유하는 것들은 워커가 가질 수 없는 **전체 맥락 + 사용자 대화 스레드**를 요구한다.
- 워커 결과는 요약으로 받고, 핵심 1~2개를 교차 확인 후 채택한다. 최종 판정은 투표 집계가 아니라 근거 품질 재평가다.

## 2. 위임 기준

- 도구 호출 3회 이하로 끝나는 일은 직접 한다 (워커 오버헤드가 더 큼).
- 메인이 10개+ 파일을 직접 읽게 되는 순간이 위임 신호 — Explore에 맡기고 결론·경로만 받는다.
- 독립 작업 2개 이상이면 병렬 호출. 결과가 서로 의존하면 순차.

## 3. 워커 브리핑 (컨텍스트 비공유 — 새 동료에게 하듯)

필수 5요소: **목표 / 배경 / 이미 파악한 것 / 기대 결과 형식 / 범위 제한(하지 말 것)**.
워커는 프롬프트에 넣어준 것만 본다 — 이 구조적 격리가 절단 계약의 집행 장치다.

## 4. 절단 계약 (생성 ≠ 검증)

| 역할 | 입력 스코프 | 금지 |
|------|------------|------|
| 테스트 설계 | spec·정의만 | **구현 diff 열람 금지** (확증편향 차단) |
| 리뷰 | 해당 페이즈 diff + spec | 구현자와 동일 컨텍스트 금지. finding은 현 diff/spec 불일치에 **귀속 증명**, 불명확하면 "범위 밖" |
| codex (다른 모델) | 발췌 입력 (보안 스캔 후) | 페르소나 다수결로 대체 금지 — 독립성은 codex만 제공 |

- 페이즈마다 커밋해 `git diff`를 격리한다 — 리뷰 오귀속(실측 실패모드)의 구조적 차단.

## 5. 렌즈 (구 페르소나 라이브러리의 계승)

- 검토 관점이 필요하면 렌즈당 **5~8개 질문 체크리스트**를 워커 프롬프트에 인라인한다 (예: 동시성 — 경쟁 조건? 재시도 중복? 락 범위? / 보안 — 권한 경계? 입력 검증? 내부정보 노출?).
- 이름·권위가 아니라 체크리스트가 일하게 한다. 캐스팅은 변경에서 도출한 최소만 — 고정 로스터 금지.

## 6. Workflow 도구 (대규모 fan-out — 사용자 opt-in)

- 높은 stakes 대규모의 다차원 검증(find → adversarial verify → synthesize)은 Workflow 스크립트로 — 순서·격리를 산문이 아니라 코드가 강제한다.
- 사용자가 명시적으로 요청할 때만. 소·중규모는 Agent 단발 호출로 충분하다.
