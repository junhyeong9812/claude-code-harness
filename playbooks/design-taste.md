# playbook: 설계 품질·취향 (design-taste)

> 트리거: `review.md §3` "설계 품질·취향" 렌즈를 적용할 때 + `implementation.md §0` 설계 시. **렌즈 판단질문 본체는 review.md §3 단일 출처** — 이 문서는 그 렌즈가 끌어 쓰는 카탈로그(*무엇이* 좋은 설계인가)다.
> 출처: `read-the-damn-code-study/TASTE.md`(8앵커·슬롭↔오버킬) + Evans DDD · Fowler Refactoring · Beck 단순설계.
> 경계: 자원·속도(메서드 내부 렌즈)는 `review.md §4` 소유 — 여기서 중복하지 않는다. 이 문서는 **응집·경계·이름·냄새·취향**만.

## 1. 두 실패 방향 (둘 다 "커밋하지 않음"에서 온다)

- **슬롭**: 기본값으로 평균낸다 — 헤지, 불가능한 null 방어, 삼킨 catch, "둘 다 장점이라" 안 고름.
- **오버킬**: 빈 알맹이를 장식으로 — 추상 탑(`Factory<Builder<Strategy<T>>>`), 전문용어 수프, 3줄 변경에 선언문 프레임.
- 산출물마다 **의도된 강한 순간은 하나**, 나머지는 그걸 받치는 평지. → 슬롭인가, 오버킬인가, **커밋된 판단**인가.

## 2. 8앵커 (인물=출처, 앵커=개념)

| 앵커 | 코드·결정에서 | 실패 신호 |
|------|--------------|----------|
| Rams-절제 | 함수는 하나만 한다; 트레이드오프를 명명 | 의도 없는 장식 |
| Maeda-환원 | 추상 한 겹 지우면 더 짧고 읽힌다 | 작지만 신호 없는 미니멀 |
| Hoare-불변식 | PRE/POST/INVARIANT를 명시 | 암묵 불변식 · 불가능한 null 방어 |
| Carmack-원자성 | 한 관심사=한 커밋, 제목=결정 이름 | "various improvements" 혼합 |
| Bass-구성 | 제어흐름은 한 관용구(early-return *또는* 중첩, 둘 다 아님) | 경쟁하는 여러 제스처 |
| Feynman-명료 | 이름이 하는 일 그대로; 신입에 설명 가능 | 깊이를 *연기하는* 전문용어 |
| Erickson-읽힘 | API는 호출자 멘탈모델로 | 청중 무시 — 전문가에 입문서 |
| Tolkien-울림 | `dedupe_by_email`은 효과에서 파생 | 회피명(helper·util·manager) · 거짓명 |

> 막히면 범용 보조축으로 교차: 명료·위계·의도·일관·절제·관대·정직·하나의 강한 순간.

## 3. Fowler 코드 냄새 숏리스트 (이름붙은 결합·중복)

- **Long Method / 깊은 중첩**: 한 메서드가 여러 일 — 추출.
- **Feature Envy**: 메서드가 남의 객체 데이터에 더 관심 — 그 객체로 옮겨라.
- **Primitive Obsession**: 의미를 raw 타입(String·int)으로 — Value Object.
- **Data Clumps**: 늘 함께 다니는 파라미터 떼 — Parameter Object.
- **Message Chain (Demeter 위반)**: `a.b().c().d()` 사슬 — 직접 의존만 노출.
- **Duplicate / Shotgun Surgery**: 한 변경에 여러 곳을 손대야 함 — 단일 출처로.

## 4. DDD 핵심 (harness가 약한 곳 — 기술 트랜잭션 ≠ 도메인 경계)

- **용어 일관성(Ubiquitous Language)**: 같은 개념을 Order/Bill/Invoice로 혼용하지 않는다 — 코드·대화·DB가 한 단어.
- **경계(Bounded Context)**: 모듈 간 통신이 남의 도메인 모델을 직접 끌어쓰나 — 경계에서 번역(ACL).
- **Aggregate**: "이 엔티티들이 *왜* 함께 트랜잭션되나"를 답할 수 있나 — 불변식이 경계를 정한다 (기술적 트랜잭션 범위 "어디까지 묶나"와 구분 — 그건 dimensions #4 데이터 정합성의 몫).

## 5. 어떻게 쓰나

- 렌즈는 **내부 레지스터** — 읽고 쓰며 머릿속에서 돌린다. **앵커표·pass/warn/fail 스캐폴딩을 산출물에 싣지 않는다.** 남는 건 커밋된 판단뿐.
- fail이면 어느 쪽(슬롭/오버킬)·어느 앵커인지 인용 + **한 줄 수정**.
- 두 앵커가 충돌하면(절제↔관대) 자동으로 고르지 말고 **긴장을 드러낸다** — 해소는 사용자 몫.
- **취향은 finding이 아니다**(review.md §2 자격조건): 단정 가능한 결함(냄새·불변식·경계 위반)만 finding, 순수 선호는 open question으로.
