## 3. 빠뜨리기 쉬운 축

- **관찰가능성**: 트리아지 오판이 보이게 — measurement-log 규약(비활성 차원이 뒤늦게 발견된 건을 "검증이 잡은 결함" 열에 `트리아지 오판(차원n·발견단계)` 형식으로 기입).
- **보안·권한**: codex 호출 시 기존 외부 전송 게이트(보안 스캔) 적용. 그 외 해당 없음(로컬 문서).
- **시간·동시성 / 외부 경계**: 해당 없음.

## 4. 검증 매핑

| 불변식 | 검증 |
|--------|------|
| dimensions.md ≤200줄·차원당 ≤10줄 | `wc -l` + 차원 블록 줄 수 확인 |
| core.md 증가 ≤5줄 | `git diff --stat core.md` |
| 단일 출처 (질문 중복 기재 없음) | core·templates에 질문 본문이 없는지 grep |
| **실효성: 신선 컨텍스트에서 트리아지가 실제 작동** | Fable 에이전트(시나리오 검증): core+dimensions+task 템플릿만 주고 모의 작업 2건(중간 1·낮음 1)의 트리아지 수행 → 형식 준수·증거 인용·stakes 도출 확인 |
| 차원 완전성·설계 함정 | codex 계획 검토 1회 + 최종 검증 1회 (높음 의무) + WebSearch 1회(production readiness checklist 유사 사례 — codex가 이미 W-A·12factor·ASVS ground, 보완용) |
| 배포 동기 | `diff -rq` repo ↔ ~/.claude = 0건 |

**다단계 판정**: 독립 변경 단위는 ① dimensions.md 신설 ② core·템플릿 배선(①에 의존, 소규모). ②는 독립 검증 단위라기보다 ①의 배선이므로 **다단계 아님** — definition+task.md 경로, 단 커밋은 ①·② 분리(diff 격리).
